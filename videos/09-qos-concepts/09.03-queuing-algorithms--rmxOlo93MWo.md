## Цель для обучающегося

Понять четыре алгоритма организации очередей и чем они отличаются:
- **FIFO** (first-in, first-out) — фактически отсутствие QoS: пакеты выходят в том же порядке, в каком вошли, без классов и приоритетов.
- **WFQ** (Weighted Fair Queuing) — автоматически классифицирует и приоритизирует пакеты по весу/потокам; высокоприоритетные уходят раньше. Настраиваемых классов нет.
- **CBWFQ** (Class-Based WFQ) — классы трафика, определяемые администратором: разным типам задаётся гарантированная полоса/приоритет.
- **LLQ** (Low Latency Queuing) — добавляет к CBWFQ строгую приоритетную очередь (PQ) для чувствительного к задержкам трафика (прежде всего голоса), чтобы звонки не прерывались.

Текст темы (9.3.2–9.3.6) подробно разбирает каждый алгоритм, значения по умолчанию (FIFO на интерфейсах выше E1; WFQ по умолчанию на serial ≤ E1), ограничения WFQ (не работает с туннелированием/шифрованием), устройство CBWFQ (bandwidth, queue-limit, tail drop) и роль PQ в LLQ. Видео — краткий визуальный обзор тех же четырёх схем. Это обзорный «крючок» перед теорией и практикой MQC; CLI в ролике нет.

**Замечания о точности оригинала:**

1. На слайде LLQ порядок выхода подписан «2 1 3 4 V V», тогда как смысл LLQ — голос (V) обслуживается **первым**. В тексте темы (9.3.6) правильный порядок: «V, V, 4, 3, 1, 2». Это похоже на ошибку/несогласованность подписи на слайде Cisco — **в remake голос должен выходить первым**.
2. Видео не упоминает значения по умолчанию (FIFO на интерфейсах > E1; WFQ по умолчанию на serial ≤ E1) и ограничения WFQ (не работает с туннелированием/шифрованием) — это есть в тексте, добавить в remake.
3. «FIFO = absence of QoS» — дидактически верно, но формально FIFO тоже алгоритм очереди (по умолчанию); уточнить формулировкой «QoS не применяется».

## Предложение по пересборке

**Формат:** `анимация Figma (≤ 60 с)` — четыре схемы очередей с анимацией прохождения пакетов; идеально ложится в анимацию. Устройств/CLI нет.

**Сцены (сцена → визуал → дикторский текст):**

| Сцена | Визуал | Дикторский текст (RU) |
|---|---|---|
| 1. FIFO | Одна очередь: пакеты входят и выходят в том же порядке; подпись «нет приоритетов». | «FIFO — одна очередь, порядок не меняется. QoS не применяется: важный пакет ждёт наравне со всеми.» |
| 2. WFQ | Классификатор делит поток на классы по весу; высокий класс выходит раньше; подпись «авто, без настройки». | «WFQ автоматически делит трафик на потоки и даёт вес: приоритетное уходит раньше. Классы не настраиваются.» |
| 3. CBWFQ | Администратор задаёт Class 1/2/3 (по ACL/протоколу); каждому — гарантированная полоса. | «CBWFQ — классы задаёт администратор и назначает каждому гарантированную полосу. Так голосу или видео резервируется ресурс.» |
| 4. LLQ | К CBWFQ добавлена строгая Priority Queue; голос (V) выходит ПЕРВЫМ, затем классы. | «LLQ добавляет строгую приоритетную очередь поверх CBWFQ: голос обслуживается раньше всего — минимальная задержка и джиттер, звонки не рвутся.» |

**Ассеты для отрисовки:** четыре схемы (`assets/9.3.3.svg` FIFO, `9.3.4.svg` WFQ, `9.3.5.svg` CBWFQ, `9.3.6.svg` LLQ) — переработать в анимацию, **исправив порядок выхода в LLQ (голос первым)**.

**Для симулятора (семя тренинга):** сам ролик без CLI, но тема прямо ведёт к настройке LLQ/CBWFQ через MQC на IOS. Пример учебной сессии для последующего lab:

```text
R1(config)# class-map match-all VOICE
R1(config-cmap)#  match ip dscp ef
R1(config-cmap)# exit
R1(config)# class-map match-all VIDEO
R1(config-cmap)#  match ip dscp af41
R1(config-cmap)# exit
R1(config)# policy-map WAN-EDGE
R1(config-pmap)#  class VOICE
R1(config-pmap-c)#   priority percent 10          ! строгий приоритет (LLQ) для голоса
R1(config-pmap-c)#  class VIDEO
R1(config-pmap-c)#   bandwidth percent 30          ! гарантированная полоса (CBWFQ)
R1(config-pmap-c)#  class class-default
R1(config-pmap-c)#   fair-queue                    ! WFQ для остального
R1(config-pmap-c)# exit
R1(config)# interface Serial0/0/0
R1(config-if)#  service-policy output WAN-EDGE
R1(config-if)# end
R1# show policy-map interface Serial0/0/0
```
