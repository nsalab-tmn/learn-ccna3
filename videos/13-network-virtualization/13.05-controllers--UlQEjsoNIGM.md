## Что это и почему «маркетинг»

Шестиминутный ролик TechWiseTV (ведущий Cisco) с тезисом «сеть должна стать application-centric, и Cisco ACI это уже сделала». Технического содержания — три понятия, ровно те, что раскрыты в тексте 13.5.3–13.5.4 курса:

- **Application Network Profile (ANP)** — «логическая карта того, как приложение выглядит, подключается и обслуживается в любой точке сети»; политика «едет» вместе с приложением и исчезает, когда приложение выводят из эксплуатации (сцена 4:00–4:30: три базы данных «dev/test/prod», коробки «ACI», мусорная корзина).
- **Фабрика ACI = контроллер APIC + коммутаторы** в топологии spine–leaf, «линейная масштабируемость, многопутёвость, оптимизация под east-west трафик; каждый добавленный spine — ещё один путь для балансировки» (сцена 4:45–5:15: ряд «SPINE» из четырёх коробок ACI и ряд «LEAF» из четырёх, зелёные линии full-mesh, цветные цилиндры-БД на связях; затем коробка APIC над фабрикой).
- **Stateless hardware** — «APIC проталкивает логическую топологию и политики вниз на коммутаторы без состояния»; APIC «открывает северный API ко всем функциям управления, южный API — сторонним сетевым сервисам».

Остальное — риторика: история «силосов» (storage / compute / network, 0:15), консолидация ЦОД (здание Cisco, 0:30), гипервизор («самый большой скачок оптимизации», светящийся сервер 0:45), «separation anxiety» виртуальных машин (ребёнок с табличкой VM, 1:00), доска «USER IN USA» с разрастающимися кружками VLAN/VPN/ACL/BYOD (1:15–2:15) и пластыри «SDN» и «NV» поверх неё (2:15–2:30), «нам нужен do-over» (доска стирается), три требования на электронной читалке («1 — приложение прежде всего», «2 — Apps Can't be Touched», «3 — keep it simple»), объяснение «что такое приложение» (web tier → app tier → DB tier + QoS/балансировка/безопасность между ними — «NOT THE APP!», 3:15–3:45), финальный плакат «Seamless mobility · physical · virtual · geographic · top-down control · bottom-up visibility · atomic counters · real-time telemetry» (5:30). Подача ориентирована на продажу продукта, а не на формирование навыка; факты о leaf-spine и ANP в тексте изложены точнее (например, в тексте явно сказано, что APIC не управляет каналом данных напрямую, а в ролике это размыто).

## Рекомендация

**Убрать.** Текст 13.5.2–13.5.4 уже содержит всё полезное (ANP, APIC, Nexus 9000, spine–leaf, роль APIC). При желании сохранить «мотивационную» часть — заменить одной фразой в 13.5.2:

> «Cisco ACI переворачивает традиционный подход: вместо привязки политики к VLAN, подсетям и правилам межсетевого экрана политика описывается в профиле приложения (ANP), а контроллер APIC сам программирует фабрику коммутаторов spine–leaf под нужды приложения и убирает политику, когда приложение выводится из эксплуатации.»

Если понадобится иллюстрация — одна статичная схема «ANP → APIC → фабрика spine–leaf (Nexus 9000)» уже есть в курсе (`assets/13.5.3.svg`, `assets/13.5.4.svg`); отдельная анимация не требуется.
