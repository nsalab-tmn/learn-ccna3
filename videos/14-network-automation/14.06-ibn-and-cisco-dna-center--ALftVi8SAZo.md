## Цель для обучающегося

Обучающийся должен понимать, что в области Design контроллер IBN описывает **намерение для целой сети**: иерархию сайтов (Global → континент → страна → здание), общие сетевые службы (AAA/ISE с RADIUS/TACACS, DHCP, DNS, Syslog, SNMP, NTP, часовой пояс, баннер), учётные данные, которыми контроллер будет входить на устройства (CLI, SNMPv2c/v3, HTTPS), пулы адресов, профили провайдеров с моделями QoS, параметры SSID (голос/данные, Fast Lane, широковещание, диапазоны, безопасность) и репозиторий образов ОС с «золотыми» версиями по семействам устройств; а в области Provision — применить всё это к обнаруженным устройствам, в т. ч. обновить ОС одним действием из инвентаря.

Текст 14.6.5 ограничивается определениями областей Design («моделирует всю сеть…») и Provision («предоставление новых услуг…»). Видео добавляет **конкретные формы и значения**: какие именно параметры задаются на уровне сайта, как выглядят учётные данные устройств и пул адресов, какие опции есть у SSID, как устроен репозиторий образов (Family / Image / Using / Version / Golden / Role) и как из инвентаря (Device Name, IP, Site, Serial, Uptime, OS Version, OS Image, Sync/Credential Status) запускается обновление ОС — это и есть «намерение → активация» из 14.6.2 в действии.

## Предложение по пересборке

**Формат:** видео с генерированным голосом (код-рендер; упрощённый макет GUI контроллера), ~2:30. Для симулятора — макет «контроллера» с тремя формами (сетевые службы сайта, учётные данные устройств, инвентарь с действием «обновить образ») + эквивалент через Intent API, чтобы показать, что GUI и API делают одно и то же; параллельно — CLI-эквивалент на устройстве (что контроллер фактически настроит: `aaa`, `ntp server`, `ip name-server`, `logging host`, `snmp-server community`, `banner motd`), чтобы связать с предыдущими модулями.

**Сцены (сцена → визуал → озвучка):**
1. Макет: дерево сайтов + карта с четырьмя метками (SE1, NY1, 9, 2) → «Сначала контроллер узнаёт, где и какие у нас сайты».
2. Форма «Сетевые службы сайта»: AAA/ISE 172.28.28.105 (TACACS для устройств, RADIUS для клиентов), DHCP/DNS 192.168.101.105, домен cisco.com, NTP 10.254.10.1, TZ PST8PDT, MOTD; справа появляется CLI-эквивалент для одного коммутатора → «Эти настройки контроллер применит ко всем устройствам сайта — вместо ввода на каждом».

CLI-эквивалент того, что контроллер применит на устройстве из «Network Settings» (для сцены 2):

```

Switch(config)# clock timezone PST -8 0
Switch(config)# clock summer-time PDT recurring
Switch(config)# logging host 192.168.101.105

Switch(config-server-tacacs)# address ipv4 172.28.28.105
Switch(config-server-tacacs)# key <shared-secret>
Switch(config)# aaa new-model
Switch(config)# aaa authentication login default group tacacs+ local
```

**Замечания к оригиналу (исправить при пересборке):**
- Диктор: «creds — probably cisco cisco» — демонстрационные учётные данные; в пересборке подчеркнуть, что для контроллера заводят отдельную учётную запись с ограниченными правами и SNMPv3.
- «HTTPS поддерживается, но не используется» — у современных устройств (IOS XE 16.x) HTTPS/RESTCONF — основной канал телеметрии; в пересборке показать заполненным.
- DNA Center → **Catalyst Center** (переименование 2023 г.); формы в новых версиях перекомпонованы; поэтому — макет, а не скриншоты.
- Диктор говорит «SP profiles — server provider» — правильно **service provider**.
- В видео обновление ОС запускается, но результат не показан (ролик обрывается на «I love it»); в пересборке довести сцену до изменения версии в инвентаре.
