## Цель для обучающегося

Обучающийся должен узнавать интерфейс контроллера IBN (Cisco DNA Center, ныне Catalyst Center): что показывает стартовая страница (здоровье устройств и клиентов за 24 ч, снимок сети — сайты, устройства, политики, профили, образы, лицензии), за что отвечает каждая из пяти областей меню, и где находится каталог Intent API (Platform → Developer Toolkit), в котором каждый вызов описан методом HTTP (GET/POST), параметрами и может быть выполнен прямо из GUI (Try It) или скопирован как код (Code Preview). Это связывает тему IBN (14.6.2–14.6.5) с темами API/REST (14.3–14.4).

Текст 14.6.5 даёт скриншот стартовой страницы (`assets/14.6.5.png` — те же цифры 87/90/98 %) и перечисляет пять областей с определениями. Видео добавляет: живую навигацию, **конкретные цифры демо-сети** (12 сайтов по континентальным США, 77 устройств, 14 незаявленных, 26 неподготовленных, 15 профилей, 58 образов, 66 лицензий: 34 коммутатора, 12 маршрутизаторов, 20 точек доступа), подписи-ссылки каждой области и **каталог API** с примерами (GET Get Site Health, POST Assign Device To Site, POST Create Site) и карточку параметров запроса — то, чего в тексте нет вовсе.

## Предложение по пересборке

**Формат:** видео с генерированным голосом (код-рендер; GUI воспроизвести как упрощённый макет контроллера в нашем стиле, не скриншоты), ~2:30. Для симулятора — макет «панели контроллера» (стартовая страница + пять областей) и, главное, **API-сеанс** к контроллеру (аутентификация, GET здоровья сайтов, POST назначения устройства), который можно выполнить из встроенного HTTP-клиента/Python. Название продукта в озвучке — «контроллер (Cisco DNA Center, сейчас Catalyst Center)».

**Сцены (сцена → визуал → озвучка):**
1. Макет стартовой страницы контроллера: три «здоровья» (83 / 90 / 98 %), шесть карточек снимка сети с цифрами из видео → «Контроллер IBN показывает состояние всей сети: 12 сайтов, 77 устройств…».
2. Пять карточек областей появляются по очереди с одной строкой-назначением каждая (взять формулировки из 14.6.5) → озвучка 1:52–3:36 сжато.
3. Макет каталога API: таблица Method/Name/Description (GET Get Site Health; POST Assign Device To Site; POST Create Site) → «Всё, что умеет GUI, доступно через Intent API».
4. Код-рендер: `POST /dna/system/api/v1/auth/token` → токен; `GET /dna/intent/api/v1/site-health` → JSON с `siteName`, `networkHealthAverage`; `POST /dna/system/api/v1/site/{siteId}/device` с телом `{"device":[{"ip":"10.41.54.201"}]}` → `executionId` → «Те же действия — из программы».

**Активы:** макет шапки контроллера с пятью вкладками; карточки «здоровья» и «снимка сети»; таблица каталога API; стиль JSON.

```python
import requests
from requests.auth import HTTPBasicAuth

DNAC = "https://dnac.example.local"
token = requests.post(f"{DNAC}/dna/system/api/v1/auth/token",
                      auth=HTTPBasicAuth("admin", "password"), verify=False).json()["Token"]
hdr = {"X-Auth-Token": token}
health = requests.get(f"{DNAC}/dna/intent/api/v1/site-health", headers=hdr, verify=False).json()
for site in health["response"]:
    print(site["siteName"], site["networkHealthAverage"])
```

**Замечания к оригиналу (исправить при пересборке):**
- Cisco DNA Center с 2023 г. называется **Catalyst Center**; интерфейс и пути API изменились (версия Platform 1.0.3 / DNA Center 1.3 в видео — 2019 г.). В пересборке говорить «контроллер» и показывать обобщённый макет.
- Диктор относит к управляемым устройствам «firewalls» — межсетевые экраны DNA Center напрямую не подготавливает; корректнее «маршрутизаторы, коммутаторы, точки доступа, контроллеры WLAN».
- В снимке сети «Images 58: Untagged 52, Unverified 52» — стоит пояснить термины golden image / tagged, иначе цифры повисают.
- Вступительная шутка про «CLI — настоящая сила» и «это сила» в конце — убрать.
