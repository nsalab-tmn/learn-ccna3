## Цель для обучающегося

Обучающийся должен понимать, что формат данных — это структурированный, машиночитаемый и одновременно читаемый человеком способ хранения и обмена данными; знать общие свойства (синтаксис, объекты, пары ключ/значение, типы значений — строки/числа/булевы/объекты/списки, сериализация); уметь узнать и сравнить XML (теги, атрибуты), JSON (`"ключ": значение`, `{}` объекты, `[]` массивы, запятые) и YAML (отступы вместо скобок, без кавычек и запятых, `-` для элементов списка), и прочитать одну и ту же сетевую структуру (интерфейс с адресом, маской и шлюзом) в каждом из них.

Текст темы (14.2.2–14.2.8) покрывает то же: концепцию формата (аналогия с меню), правила (синтаксис, объекты, ключ/значение), пример JSON с положения МКС, сравнение форматов на одном объекте (`ietf-interfaces:interface` / GigabitEthernet0/0/0, 172.16.0.2/24), синтаксис JSON, YAML, XML. Видео добавляет: наглядный мостик от **HTML** (разметка → браузер) к форматам данных; понятие **сериализации** на живом примере `JSON.stringify` объекта JavaScript → строка; сжатые таблицы-сравнения свойств трёх форматов; **параллельный разбор вложенности** (`network-settings` → `interface` → `GigabitEthernet0` → `ipaddress`/`netmask`/`gateway`) с указанием, чем задаётся структура в каждом формате (теги / скобки и запятые / отступы и дефис).

## Предложение по пересборке

**Формат:** видео с генерированным голосом (код-рендер), ~2:30. Содержание почти целиком есть в тексте, но параллельный показ одной структуры в трёх форматах с подсветкой «что задаёт вложенность» — именно то, что выигрывает от видео. Вводную часть (HTML, пять свойств) сократить до одной сцены; использовать **пример из текста курса** (`ietf-interfaces:interface`, GigabitEthernet0/0/0, 172.16.0.2/24), чтобы видео и текст совпадали.

**Сцены (сцена → визуал → озвучка):**
1. Слева фрагмент вывода `show interface GigabitEthernet0/0/0` (как в 14.2.5), справа появляются три пустые карточки «XML / JSON / YAML» → «Один и тот же факт — адрес интерфейса — можно записать для машины по-разному».
2. Карточка «Свойства»: структурированно · читаемо человеком · ключ/значение · значения: строка, число, булево, объект, список · сериализация (объект → строка → объект) → «У всех форматов общие свойства…».
3. Код-рендер JSON (из 14.2.5), построчное появление; подсветка `{ }` объектов, `[ ]` массива `address`, запятых; `"enabled": true` как булево → «JSON: ключ в кавычках, двоеточие, запятые, фигурные скобки — объекты, квадратные — списки».
4. Код-рендер YAML (из 14.2.7) рядом с JSON: подсветка отступов и `-` у элемента списка; исчезающие кавычки/запятые → «YAML: структуру задают отступы, элемент списка — дефис».
5. Код-рендер XML (из 14.2.8): подсветка парных тегов и вложенности → «XML: ключ — это тег, значение между тегами, вложенность — тег в теге».
6. Финальный кадр: три формата бок о бок, одна и та же подсвеченная цепочка `interface → ipv4 → address → ip` → «Одна структура — три синтаксиса; выбор зависит от инструмента: REST API чаще отдают JSON, Ansible пишется на YAML, NETCONF говорит XML».

**Активы:** стиль терминала и подсветки для трёх форматов; пиктограммы «объект / список / строка / число / булево».

**Замечания к оригиналу (исправить при пересборке):**
- Пример в видео (`network-settings`/`GigabitEthernet0`, 192.168.0.100) не совпадает с примером в тексте (`ietf-interfaces:interface`, 172.16.0.2/24); при пересборке взять один.
- В XML-примере `xmlns="network interfaces"` — пространство имён должно быть URI без пробелов; в пересборке либо убрать `xmlns`, либо дать корректное (`urn:ietf:params:xml:ns:yang:ietf-interfaces`, как в 14.2.8).
- Отступ в YAML-примере — один пробел; общепринятый стиль — два пробела; при пересборке использовать два.
- «YAML новее XML и JSON» — спорно: YAML (2001) и JSON (2001) появились одновременно; корректнее сказать «YAML набирает популярность в инструментах автоматизации (Ansible)».
- `JSON.stringify(spriteObject = {...})` — присваивание внутри вызова; для учебного примера лучше два шага: объявить объект, затем `JSON.stringify(spriteObject)` и парный `JSON.parse(...)`.
