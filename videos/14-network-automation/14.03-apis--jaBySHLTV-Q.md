## Цель для обучающегося

Обучающийся должен уметь объяснить, что API — «посредник» между двумя программами (готовый код, которому нужно лишь правильно задать вызов), назвать четыре популярных API/протокола сетевой автоматизации (SOAP — HTTP+XML; REST — HTTP, JSON/XML; NETCONF — SSH+XML, замена SNMP; RESTCONF — REST-подобный, XML/JSON, связан с YANG) и **выполнить вызов публичного REST API тремя способами**: из адресной строки браузера, из Postman (выбор метода GET/POST/PUT/DELETE, URL, ключ, ответ 200 OK с JSON) и из кода (JavaScript `XMLHttpRequest` → `JSON.parse` → поля `title`, `url`).

Текст темы (14.3.2–14.3.5) даёт определение API через аналогию с официантом, пример сайта-агрегатора авиабилетов, типы API (открытые/внутренние/партнёрские) и таблицу веб-сервисов (SOAP, REST, XML-RPC, JSON-RPC). Видео добавляет: NETCONF и RESTCONF как сетевые API (в тексте их нет до 14.4); **конкретный живой вызов API** с реальным URL, ключом `DEMO_KEY`, полным JSON-ответом и кодом на JavaScript, который этот ответ разбирает — это единственный в модуле показ «API в действии» и готовая основа для упражнения в симуляторе.

## Предложение по пересборке

**Формат:** видео с генерированным голосом (код-рендер), ~3:00: короткая вводная (определение + четыре API) и три способа вызова одного и того же публичного REST API. Слайдовую часть сократить до двух карточек; живую часть сделать основной. Тот же сеанс — упражнение для симулятора (встроенный HTTP-клиент / «Postman-lite» и консоль с Python вместо JavaScript — в курсе далее используется Python).

**Сцены (сцена → визуал → озвучка):**
1. Карточка «API = посредник»: клиент → [API] → сервис; подпись «готовый код — нужно знать только вызов» → «API — способ двум программам общаться…».
2. Карточка «Четыре API сетевой автоматизации»: SOAP (HTTP+XML) · REST (HTTP, JSON/XML) · NETCONF (SSH+XML, вместо SNMP) · RESTCONF (HTTP, JSON/XML, YANG) → озвучка по слайду 1:13.
3. Браузер (стилизованный): адресная строка `https://api.nasa.gov/planetary/apod?api_key=DEMO_KEY` → JSON-ответ с подсветкой ключей `title`, `url`, `date` → «REST-вызов — это обычный HTTP GET; ответ — JSON».
4. Панель HTTP-клиента: селектор метода (GET/POST/PUT/DELETE), URL, параметр `api_key=DEMO_KEY`, Send → `200 OK`, тело → «Инструменты вроде Postman показывают метод, параметры, статус и тело».
5. Код-рендер (Python, чтобы совпасть с 14.5–14.6 курса):<br>`import requests`<br>`r = requests.get("https://api.nasa.gov/planetary/apod", params={"api_key": "DEMO_KEY"})`<br>`data = r.json()`<br>`print(data["title"]); print(data["url"])` → вывод `The Elephant's Trunk Nebula in Cepheus` и URL → «Из программы: отправили запрос, разобрали JSON, взяли нужные поля».
6. (опц.) Тот же вызов на JavaScript `fetch()` одной карточкой — для тех, кто пишет под браузер.

**Активы:** иконки клиент/API/сервис; макет HTTP-клиента; стиль кода для JSON/Python.

Оригинальный JavaScript из видео (для варианта «в браузере»):

```html
<p id="output"></p>
<img src="" width="600">
<script>
var output = document.querySelector("#output");
var image = document.querySelector("img");
var request = new XMLHttpRequest();
request.onreadystatechange = function() {
  if (this.readyState == 4 && this.status == 200) {
    var o = JSON.parse(request.responseText);
    output.innerHTML = o.title;
    image.src = o.url;
  }
};
request.open("GET", "https://api.nasa.gov/planetary/apod?api_key=DEMO_KEY", true);
request.send();
</script>
```

**Замечания к оригиналу (исправить при пересборке):**
- «SOAP — стандарт, разработанный Microsoft»: SOAP создан в 1998 г. группой с участием Microsoft (Box, Kakivaya и др.) и стандартизован W3C; формулировка «designed by Microsoft» упрощает, лучше «стандарт W3C, изначально разработан при участии Microsoft».
- «NETCONF uses SSH and XML», «RESTCONF… coupled to YANG… like NETCONF» — верно, но в видео не сказано, что NETCONF тоже использует YANG; в пересборке — «оба используют модели YANG, NETCONF — по SSH с XML, RESTCONF — по HTTPS с XML или JSON».
- Для симулятора публичный API NASA требует Интернета; в симуляторе заменить на локальную заглушку с тем же контрактом (`/planetary/apod` → тот же JSON) или на RESTCONF-эндпойнт эмулируемого маршрутизатора, что ближе к теме курса.
- `XMLHttpRequest` — устаревший API; в пересборке на JavaScript использовать `fetch()`.
