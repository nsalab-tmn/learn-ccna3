## Цель для обучающегося

Обучающийся должен понимать, почему CLI и SNMP плохо подходят для автоматизации, и что инструменты управления конфигурацией (Ansible, Puppet, Chef, SaltStack) делают это через скрипты-«рецепты»; знать язык и единицу описания каждого инструмента (Ansible — Python + YAML, playbook; Puppet — Ruby, manifest; Chef — Ruby, cookbook; SaltStack — Python, pillar); уметь прочитать Ansible-playbook — выделить plays (`name`, `hosts`), tasks, modules (`debug`, `command`), parameters (`msg`), variables (`{{ … }}`, факты `ansible_hostname`, `ansible_distribution`, `ansible_default_ipv4.interface`, `register: routes`) — и интерпретировать вывод `ansible-playbook` (PLAY / TASK / Gathering Facts / ok / changed / PLAY RECAP).

Текст темы (14.5.2–14.5.5) даёт то же введение (CLI, SNMP/NMS, API), список технологий, определения автоматизации/оркестрации и таблицу сравнения четырёх инструментов (язык, агент/без агента, мастер, playbook/cookbook/manifest/pillar). Видео добавляет: **реальный playbook** с построчным разбором терминов и **реальный запуск** с выводом (включая предупреждения о sftp/scp и структуру `register`-переменной с `stdout_lines`), которого в тексте нет. Это единственная в модуле демонстрация инструмента управления конфигурацией в работе.

Полный текст playbook `example1.yaml` (со слайда и из `cat`):

```yaml
- name: Report Hostname and Operating System Details
  hosts: servers

  tasks:
    - name: "Get hostname from server"
      debug:
        msg: "{{ansible_hostname}}"

    - name: "Operating System"
      debug: msg="{{ansible_distribution}}"

- name: Report Network Details of Servers
  hosts: servers

  tasks:
    - name: "Default IPv4 Interface"
      debug: msg="{{ansible_default_ipv4.interface}}"

    - name: "Retrieve network routes"
      command: "netstat -rn"
      register: routes

    - name: "Network routes installed"
      debug: msg="{{routes}}"
```

**Замечания к оригиналу (исправить при пересборке):**
- «SaltStack uses pillars» как единица описания (и так же в таблице 14.5.5): в Salt конфигурация описывается **state-файлами (SLS)**, а pillar — хранилище данных/секретов для них. В пересборке: «SaltStack — states (SLS), данные — pillar».
- Диктор говорит «netstack command» — команда `netstat`; и «-user parameter» — в терминале набрано `-u`.
- Пример запускается против Linux-хоста (devbox в DevNet sandbox), а не сетевого устройства; для курса CCNA убедительнее показать `ios_facts`/`ios_command` (см. сетевой вариант) — тогда видео прямо поддержит 14.5.4 («атрибуты устройства, конфигурации протоколов, ACL»).
- Предупреждения `sftp/scp transfer mechanism failed` — особенность окружения (отсутствует sftp-subsystem у цели, Ansible переходит на piped-транспорт), не часть урока; в пересборке убрать или пояснить одной фразой.
- Окружение `py2-venv` (Python 2) и Ansible 2019 года — устарело; в пересборке Python 3 и коллекции `cisco.ios`.
