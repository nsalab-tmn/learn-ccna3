## Цель для обучающегося

Обучающийся должен понимать, что REST — каркас веб-API поверх HTTP(S), а RESTCONF — REST-подобный протокол управления сетевыми устройствами с моделями YANG и хранилищами данных NETCONF; знать соответствие методов HTTP операциям CRUD (POST — create, GET — read, PUT/PATCH — update, DELETE — delete); уметь разобрать URI запроса API на сервер, ресурс и запрос (формат, ключ, параметры); и **выполнить один и тот же REST-вызов четырьмя способами** — в браузере, через `curl`, из JavaScript и из Python — получив JSON и вытащив из него нужные поля.

Текст темы (14.4.2–14.4.6) объясняет REST/RESTful (клиент-сервер, stateless, кешируемость), таблицу методов и CRUD, URI/URN/URL, анатомию запроса на примере MapQuest Directions (тот же URI, что на слайде видео), способы вызова (сайт разработчика, Postman, Python — скриншотами) и сеанс NETCONF. Видео добавляет **реальный исполняемый пример** с публичным API геолокации `ipinfo.io` — полный JSON-ответ, команда `curl` с выводом, 23-строчный JavaScript и 12-строчный Python с результатом; именно эти четыре эквивалентных вызова — основа упражнения для симулятора.

## Предложение по пересборке

**Формат:** видео с генерированным голосом (код-рендер), ~3:00; и сеанс для симулятора. Слайдовую часть свести к двум карточкам (методы↔CRUD; анатомия URI — рисунок уже есть в курсе), основное время — четыре эквивалентных вызова одного API с одинаковым JSON, чтобы было видно: меняется инструмент, не меняется протокол.

**Сцены (сцена → визуал → озвучка):**
1. Карточка «REST = API поверх HTTP» + мини-таблица `POST→Create · GET→Read · PUT/PATCH→Update · DELETE→Delete` → озвучка 0:48–1:31 сжато.
2. Карточка «Анатомия URI» (из `assets/14.4.5-1.svg`): подсветка по очереди «сервер API», «ресурс», «запрос: формат, ключ, параметры» → озвучка 1:31–2:32.
3. Стилизованный браузер: адресная строка `https://ipinfo.io/72.163.4.185/json` → JSON; подсветить `region`, `country`, `org` → «GET из адресной строки».
4. Терминал: `curl https://ipinfo.io/72.163.4.185/json` → тот же JSON → «тот же запрос из командной строки».
5. Код-рендер Python (вариант с `requests` — так в 14.4.6-3 курса): запрос → `r.json()` → `print(data["ip"], data["org"])` → «из программы: отправили, разобрали, взяли поля».
6. Код-рендер JavaScript (`fetch`) одной карточкой → «то же в браузерном коде».
7. Финал: четыре окна рядом, одна и та же строка `72.163.4.185 - AS109 Cisco Systems, Inc.` → «Инструменты разные, запрос один».

`main.py` (как в видео; для пересборки — вариант на `requests` ниже):

```python
import json, urllib.request

#ip location information

url = "https://ipinfo.io/72.163.4.185/json"
response = urllib.request.urlopen(url)
result = json.loads(response.read())

print("ip: " + str(result["ip"]))
print("org: " + str(result["org"]) + "\r\n")

print("Response: " + str(result))
```

```python
import requests

r = requests.get("https://ipinfo.io/72.163.4.185/json")
data = r.json()
print("ip:", data["ip"])
print("org:", data["org"])
```

**Замечания к оригиналу (исправить при пересборке):**
- Заголовок слайда «URI **Universal** Resource Identifier» — правильно **Uniform** Resource Identifier (как и в тексте 14.4.4).
- Диктор: «PUT — when you're sending data to the server; PATCH — small change» — точнее: PUT заменяет ресурс целиком, PATCH изменяет часть; в тексте оба отнесены к Update — так и озвучить.
- Диктор: RESTCONF «uses … NETCONF to find data stores» — корректно: RESTCONF обращается к тем же хранилищам (datastores) и моделям YANG, что и NETCONF, но по HTTPS.
- `ipinfo.io` без токена отвечает ограниченно (`"readme": "https://ipinfo.io/missingauth"` — намёк на то, что без ключа часть полей недоступна); для симулятора нужна локальная заглушка с тем же JSON, не зависящая от Интернета и лимитов.
- `XMLHttpRequest` устарел — в пересборке `fetch()`; `urllib.request` в Python работает, но в курсе далее используется `requests` — лучше сразу он.
