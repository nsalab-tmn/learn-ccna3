## Цель для обучающегося

Обучающийся должен уметь по жалобе пользователя пройти путь диагностики в контроллере: найти пользователя и его устройства (ISE-интеграция), открыть Client 360 (тип устройства, MAC, IPv4/IPv6, VLAN, статус, точка доступа, SSID, местоположение, оценка здоровья), прочитать список проблем (P2 «iOS-клиент отключился от SSID», P3 «двухдиапазонный клиент предпочитает 2,4 ГГц»), в Event Viewer найти сбойное событие и его причину (KeyExchange — 4-way key timeout при широковещательном rekey на WLC-9800), а в Intelligent Capture увидеть положение клиента на плане этажа, RSSI/SNR, трафик приложений и покадровый анализ обмена 802.11 (Open Auth → Association → 802.1X/EAP → DHCP). Это конкретизация «контроля» (assurance) из 14.6.2 на уровне одного клиента.

Текст темы не описывает диагностику клиентов вовсе (14.6.5 — лишь определение Assurance). Видео добавляет полный **разбор одного кейса** с реальными значениями (iPhone 7, A8:BE:27:36:70:11, 10.30.100.45, VLAN 120, AP4800, @CorpSSID, WLC-9800, события с точностью до миллисекунд), набор инструментов Client 360 и понятие Intelligent Capture; таблицу ROI (traceroute 6 мин → мгновенно и т. п.) — маркетинг.

## Предложение по пересборке

**Формат:** видео с генерированным голосом (код-рендер; макет «Client 360» контроллера + терминал WLC), ~3:30; ROI-слайд (5:13–6:55) **убрать**. Для симулятора — сценарий «жалоба пользователя»: макет Client 360 с данными Грейс и CLI-эквивалент на контроллере WLAN (Catalyst 9800), чтобы обучающийся увидел, что GUI показывает те же данные, что `show wireless client …`.

**Сцены (сцена → визуал → озвучка):**
1. Жалоба «у Грейс отваливается Wi-Fi» → поиск `grace` → три устройства + учётная запись (ISE) → «Контроллер знает пользователя, а не только MAC-адрес».
2. Макет Client 360 для iPhone 7: MAC A8:BE:27:36:70:11, IPv4 10.30.100.45, VLAN 120, AP4800, @CorpSSID, оценка 8/10, график за сутки с красными метками → «Все параметры подключения — на одном экране».
3. Issues: P2 «iOS-клиент отключился от @CorpSSID на AP4800» ×74, P3 «клиент предпочитает 2,4 ГГц» ×61 → «Контроллер уже сгруппировал симптомы».
4. Event Viewer: цепочка Broadcast Rekey → Client Deauthenticated → **KeyExchange: 4 way Key Timeout** (WLC-9800, VLAN 120) → «Первопричина: при широковещательном обновлении ключа клиент не завершает 4-way handshake — его отключают; дальше DHCP/re-auth заново».
5. Intelligent Capture: план этажа с тепловой картой и точкой клиента; RF: RSSI ≈ −45 dBm, SNR ≈ 45 dB → «Сигнал хороший — дело не в дальности»; Auto Packet Analyzer: Open Auth → Association → 802.1X/EAP → красные кадры EAP → «Сбой на этапе обмена ключами, а не радио».
6. Терминал WLC: `show wireless client mac-address a8be.2736.7011 detail` → «Те же данные доступны и в CLI; контроллер собирает их за вас по всем 249 клиентам».
7. Вывод: «что проверять дальше» — таймеры rekey/EAP на WLC и ISE, версия iOS/профиль 802.1X.

**Активы:** макеты Client 360, списка проблем, Event Viewer, Intelligent Capture (план этажа, тепловая карта, дорожки Auto Packet Analyzer); рамка терминала.

## Транскрипт

Оригинальные авто-субтитры (английский), 20-секундные интервалы.
