## Цель для обучающегося

Понять разницу между двумя режимами ESP по тому, что именно шифруется и какой IP-заголовок используется для доставки:
- **Transport mode:** исходный IPv4-заголовок **не меняется** (виден в сети), шифруется только полезная нагрузка (TCP-заголовок + данные). Применяется для защиты трафика между конечными узлами.
- **Tunnel mode (используется в VPN-туннелях):** шифруется и инкапсулируется **весь исходный IPv4-пакет** (включая исходный заголовок), и к нему добавляется **новый внешний (публичный) IPv4-заголовок**. Так реальные адреса скрыты, а по сети пакет идёт между шлюзами туннеля.

Уметь читать структуру ESP-пакета: внешний/исходный IPv4-заголовок с `Protocol 50` (= ESP), ESP Header, зашифрованная область, ESP Trailer с полем Next Header (указывает, что внутри: TCP=6 в transport, IPv4=4 в tunnel), и необязательное ESP Authentication Data (хеш для проверки целостности от ESP Header до ESP Trailer).

Текст темы 08.03 подробно разбирает IPsec-фреймворк, AH/ESP, шифры, целостность, DH, но **форматы пакетов transport/tunnel показывает именно это видео** (в тексте 8.3.3 есть рисунок инкапсуляции, но покадрового сравнения двух режимов нет). Это главная добавочная ценность ролика.

## Сценарий

Два синих слайда-схемы формата пакета. Один мужской голос.

|---|---|---|---|---|
| 1 | 00:00–00:45 | Слайд «IPv4 Packet with ESP in Transport Mode». Горизонтальная структура слева направо: **IPv4 Header** (с выноской `Protocol 50`) · **ESP Header** · **Encrypted IP Data** (внутри: `TCP Header` + `TCP Data`) · **ESP Trailer** (с выноской `Next Header 6`) · **ESP Auth Data**. Сверху скобки: «Encrypted Fields» охватывает Encrypted IP Data + ESP Trailer; «Authenticated Fields» охватывает от ESP Header до ESP Trailer. | «В транспортном режиме есть единственный IPv4-заголовок, и он не меняется. Protocol 50 указывает, что используется ESP; добавляются ESP-заголовок и ESP-трейлер. ESP Trailer говорит, что следующий заголовок — TCP (Next Header 6): после расшифровки идёт TCP-заголовок в зашифрованных IP-данных. Есть ESP Authentication Data: если эта опция включена, выполняется проверка целостности — хешируются все поля от ESP Header до ESP Trailer, чтобы убедиться, что данные не изменены.» | Transport mode: что шифруется и аутентифицируется |
| 2 | 00:45–01:51 | Слайд «IPv4 Packet with ESP in Tunnel Mode». Структура: **New IPv4 Header** (с выноской `Protocol 50`) · **ESP Header** · **Original IPv4 Entire Packet (Encapsulated and Encrypted)** (внутри: `IPv4 Header` с `Protocol 6`, `TCP Header`, `TCP Data`) · **ESP Trailer** (с выноской `Next Header 4`) · **ESP Auth Data**. Скобки «Encrypted Fields» и «Authenticated Fields» как и раньше. | «Сравним с туннельным режимом, который используется в VPN-туннелях. Здесь шифруется и инкапсулируется весь исходный IPv4-пакет — не только данные с TCP, но и исходный IPv4-заголовок. ESP Trailer теперь указывает Next Header = IPv4 (4), потому что внутри лежит оригинальный IPv4-заголовок. Снаружи создаётся новый публичный IPv4-заголовок; он сообщает Protocol 50 (ESP), дальше ESP Header, ESP Trailer и ESP Authentication Data, если включены проверки целостности через хеширование. Такой пакет вы и увидите в ESP/VPN-туннеле: с исходным и новым внешним IP-адресом.» | Tunnel mode: инкапсуляция всего пакета + новый IP-заголовок |

**Замечания о точности оригинала:** фактических ошибок нет; схемы корректны. Значения Next Header — это номера протоколов IP: 6 = TCP, 4 = IPv4-in-IPv4 (инкапсуляция), 50 = ESP. Стоит подписать это явно при пересборке. Видеодорожка обрывается за ~2 с до конца фразы, содержание не теряется.

## Предложение по пересборке

**Формат:** `анимация Figma (≤ 60 с)` — наглядное построение ESP-пакета в двух режимах с подсветкой «что зашифровано / что аутентифицировано». Короткий ролик, идеально ложится в анимацию.

**Сцены (сцена → визуал → дикторский текст):**

| Сцена | Визуал | Дикторский текст (RU) |
|---|---|---|
| 1. Transport mode | Строится пакет: [IPv4 Hdr (Proto 50)] [ESP Hdr] [ (TCP Hdr + TCP Data) — зашифровано ] [ESP Trailer: Next=TCP(6)] [ESP Auth]. Подсветкой выделяются «зашифровано» (payload) и «аутентифицировано» (ESP Hdr…Trailer). Исходный IP-заголовок подписан «виден в сети». | «Транспортный режим: исходный IP-заголовок остаётся открытым, шифруется только полезная нагрузка — TCP-заголовок и данные. Protocol 50 означает ESP. Используется между конечными узлами.» |
| 2. Tunnel mode | Строится пакет: [New IPv4 Hdr (Proto 50)] [ESP Hdr] [ (Original IPv4 Hdr + TCP + Data) — зашифровано целиком ] [ESP Trailer: Next=IPv4(4)] [ESP Auth]. Исходный заголовок подписан «спрятан внутри», новый — «публичный, между шлюзами». | «Туннельный режим — для VPN: шифруется весь исходный пакет вместе с его IP-заголовком, а снаружи добавляется новый публичный IP-заголовок. Реальные адреса скрыты; по интернету пакет идёт между шлюзами туннеля.» |
| 3. Сводка | Две строки сравнения: что открыто, что зашифровано, где применяется. | «Коротко: transport прячет данные, оставляя адреса; tunnel прячет весь пакет и подменяет адреса на адреса шлюзов. В site-to-site VPN применяется tunnel.» |

**Ассеты для отрисовки:** два «конструктора» ESP-пакета (transport и tunnel) с цветовой подсветкой зашифрованных/аутентифицированных полей; легенда номеров протоколов (6=TCP, 4=IPv4, 50=ESP). Можно опереться на рисунок `assets/8.3.3.svg`.

**Для симулятора:** прямой CLI нет, но понимание tunnel-mode — основа для лабораторной настройки site-to-site IPsec VPN (режим задаётся в `crypto ipsec transform-set … mode tunnel`). Стоит связать с lab модуля 08.
