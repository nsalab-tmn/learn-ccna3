## Цель для обучающегося

Понять четыре элемента защищённой связи и увидеть два из них «вживую»: **целостность данных** (хеширование: любое изменение файла меняет хеш) и **конфиденциальность данных** (симметричное шифрование: один пароль-ключ шифрует и расшифровывает). Знать, что к этим двум добавляются **аутентификация источника** (сообщение действительно от заявленного отправителя) и **невозможность отказа** (non-repudiation). Понять постановку задачи: организациям нужно защищать данные и в покое, и при передаче по сети.

Текст темы 03.10 очень обширен (3.10.2–3.10.9): хеш-функции MD5/SHA-1/SHA-2, уязвимость «голого» хеша к MITM, HMAC с секретным ключом (и пример аутентификации маршрутов OSPF), симметричные алгоритмы DES/3DES/AES/SEAL/RC, асимметричные DH/DSA/RSA/ElGamal/ECC, обмен ключами Диффи — Хеллмана. Видео намного уже: это вводная GUI-демонстрация, которая делает осязаемыми только идеи целостности и конфиденциальности и в конце перечисляет все четыре элемента. Для наших материалов видео — хороший «крючок» перед теорией; глубину брать из текста.

## Предложение по пересборке

**Формат:** `видео с генерированным голосом (код-рендер)` ~2:30 (демо целостности и конфиденциальности как анимация) + `текст + иллюстрация` для теории из 03.10. Устройств/CLI нет; единственное «сетевое» применение — аутентификация маршрутов OSPF (HMAC) и VPN/IPsec (стыкуется с модулем 08).

**Сцены (сцена → визуал → дикторский текст):**

| Сцена | Визуал | Дикторский текст (RU) |
|---|---|---|
| 1. Четыре элемента | Четыре карточки: целостность, аутентификация источника, конфиденциальность, невозможность отказа. | «Защищённая связь стоит на четырёх элементах: целостность, аутентификация источника, конфиденциальность и невозможность отказа.» |
| 2. Целостность через хеш | Файл → хеш-функция → короткий хеш; меняем один символ → хеш полностью другой; сравнение «ожидалось/получено» → mismatch. | «Хеш — «отпечаток» данных фиксированной длины. Изменишь хоть один символ — хеш станет совершенно другим. Получатель пересчитывает хеш и сравнивает: совпал — данные целы, нет — изменены. Алгоритмы: MD5 и SHA-1 устарели, используйте SHA-2.» |
| 3. Почему одного хеша мало → HMAC | Злоумышленник посередине подменяет сообщение и пересчитывает хеш; затем — HMAC с секретным ключом, который он пересчитать не может. | «Голый хеш не спасает от подмены: злоумышленник заменит сообщение и пересчитает хеш. Поэтому добавляют секретный ключ — HMAC. Верный HMAC может вычислить только владелец ключа, значит заодно подтверждается и источник. Так Cisco-роутеры аутентифицируют обновления OSPF.» |
| 4. Конфиденциальность: симметрия | Аналогия коробки с одним замком (Алиса/Боб, `assets/3.10.7.svg`): один общий ключ шифрует и расшифровывает. Алгоритмы DES/3DES/AES. | «Конфиденциальность — это шифрование. В симметричном один общий ключ и шифрует, и расшифровывает — быстро, подходит для больших объёмов, например VPN. Алгоритмы: DES и 3DES устарели, стандарт — AES.» |
| 5. Асимметрия и обмен ключами | Разные ключи (открытый/закрытый), `assets/3.10.8.svg`; аналогия смешивания красок Диффи — Хеллмана, `assets/3.10.9.svg`. | «Проблема симметрии — как безопасно передать ключ. Решение — асимметрия: открытый и закрытый ключи, и обмен ключами Диффи — Хеллмана, когда стороны получают общий секрет, ни разу не передав его по сети. На практике DH/асимметрию берут для обмена ключом, а сам трафик шифруют быстрым AES.» |

**Ассеты для отрисовки:** четыре карточки элементов; анимация «изменение символа → другой хеш»; схема HMAC (`assets/3.10.5-*.svg`); аналогия коробки с замком (`3.10.7.svg`); асимметрия (`3.10.8.svg`) и краски DH (`3.10.9.svg`).

Для симулятора по IOS прямой ценности нет; смежная практическая тема — настройка аутентификации OSPF (HMAC) и выбор AES/DH в IPsec (модуль 08).
