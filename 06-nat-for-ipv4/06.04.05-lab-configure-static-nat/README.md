## Описание сценария

Преобразование сетевых адресов (NAT) заменяет IPv4-адрес в заголовке пакета, когда пакет проходит через маршрутизатор. Узлам внутренней сети организации назначают частные адреса, которые не маршрутизируются в Интернете, а NAT на пограничном маршрутизаторе подставляет вместо них публичные адреса. Статическое преобразование NAT постоянно сопоставляет один частный адрес одному публичному, поэтому сервер внутренней сети доступен из Интернета по своему публичному адресу.

Согласно сценарию, веб-сервер компании Server1 находится во внутренней сети за маршрутизатором R1 и имеет частный адрес 172.16.16.1. Провайдер выделил компании для этого сервера публичный адрес 64.100.50.1 и направляет пакеты для него на маршрутизатор R1. Клиенты в Интернете, компьютер PC1 и ноутбук L1, должны открывать веб-страницу сервера по публичному адресу. Вам, сетевому администратору компании, нужно убедиться, что сейчас сервер из Интернета недоступен, настроить на маршрутизаторе R1 статическое преобразование NAT и проверить доступ к серверу.

## Задачи лабораторной работы

- Проверить доступ к серверу Server1 из Интернета без преобразования адресов
- Настроить статическое преобразование NAT на маршрутизаторе R1
- Проверить доступ к серверу Server1 по публичному адресу и таблицу преобразований NAT

## Описание топологии

Топология состоит из маршрутизатора R1, коммутатора S1 и сервера Server1 во внутренней сети компании и маршрутизатора Internet с коммутаторами ISP-SW1 и ISP-SW2, компьютером PC1 и ноутбуком L1, которые изображают сеть провайдера и Интернет: маршрутизатор R1 соединен с маршрутизатором Internet последовательным кабелем.
