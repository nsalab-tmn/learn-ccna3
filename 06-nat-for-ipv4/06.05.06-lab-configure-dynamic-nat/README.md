## Описание сценария

Преобразование сетевых адресов (NAT) заменяет IPv4-адрес в заголовке пакета, когда пакет проходит через маршрутизатор. Узлам внутренней сети организации назначают частные адреса, которые не маршрутизируются в Интернете, а NAT на пограничном маршрутизаторе подставляет вместо них публичные адреса. Динамическое преобразование NAT выдает публичные адреса из пула: список контроля доступа (ACL) определяет, адреса каких внутренних узлов преобразуются, и каждый такой узел получает из пула свой публичный адрес, когда начинает обмен данными с внешней сетью.

Согласно сценарию, во внутренней сети компании за маршрутизаторами R1 и R2 работают компьютеры PC1 и PC2 и ноутбук L1 с частными адресами из сети 172.16.0.0/16. Провайдер выделил компании два публичных адреса, 209.165.200.229 и 209.165.200.230, и направляет пакеты для них на маршрутизатор R2. Сотрудникам нужен доступ к серверу Server1 в Интернете. Вам, сетевому администратору компании, нужно убедиться, что сейчас сервер из внутренней сети недоступен, настроить на маршрутизаторе R2 динамическое преобразование NAT с пулом из этих двух адресов и проверить, как узлы получают адреса из пула.

## Задачи лабораторной работы

- Проверить связь узлов внутренней сети с сервером Server1 без преобразования адресов
- Настроить динамическое преобразование NAT на маршрутизаторе R2
- Проверить преобразование адресов и доступ к серверу, когда все адреса пула NAT заняты

## Описание топологии

Топология состоит из маршрутизаторов R1 и R2, коммутаторов S1 и S2, компьютеров PC1 и PC2 и ноутбука L1 во внутренней сети компании и маршрутизатора Internet с коммутатором ISP-SW и сервером Server1, которые изображают сеть провайдера и Интернет: маршрутизатор R2 соединен последовательными кабелями с маршрутизатором R1 и с маршрутизатором Internet.
