<!-- 3.6.1 -->
На самом деле существует гораздо больше типов атак, чем те, которые мы обсуждали ранее. В этой теме мы рассмотрим те, что специально направлены на уязвимости IP.

Защита границы от поддельных исходных адресов — это входной список, который отбрасывает пакеты с нашим адресом, пришедшие снаружи.

1. Топология: наша сеть **192.168.1.0/24** за пограничным маршрутизатором **R1**; **ISP** — сторона провайдера.
2. Обычное состояние. С ISP команда **ping 192.168.1.10** доходит до узла внутри: обычный трафик снаружи проходит.
3. Проверка в режиме **«Симуляция»**. Администратор отправляет эхо-запрос с поддельным внутренним источником — **ping 192.168.1.10 source 192.168.1.66**: пакет с нашим адресом, пришедший снаружи, маршрутизатор пропускает внутрь, а эхо-ответ уходит на поддельный адрес. Так подделку исходного адреса используют в атаках.
4. Защита на R1. Список **access-list 120** запрещает на входе пакеты с исходными адресами нашей сети (**deny ip 192.168.1.0 0.0.0.255 any**), частных диапазонов (**10.0.0.0**, **172.16.0.0**, **192.168.0.0**) и петли (**127.0.0.0**), затем **permit ip any any**; применяют на интерфейсе к провайдеру — **ip access-group 120 in** на G0/0/0.
5. Та же проверка вживую. Тот же **ping 192.168.1.10 source 192.168.1.66** снаружи теперь дает `.....` — пакеты отброшены на границе, а обычный **ping 192.168.1.10** проходит (`!!!!!`). **show access-lists** показывает счетчики совпадений на запрещающих строках.
6. Итог: на входе со стороны провайдера — ACL: адреса нашей сети, частные адреса и петля запрещены, остальное разрешено. Проверка: пакет с поддельным источником отброшен и посчитан, обычный трафик проходит.

## IPv4 и IPv6

IP не проверяет, действительно ли указанный в пакете IP-адрес источника поступил из этого источника. Поэтому злоумышленники могут отправлять пакеты, используя поддельный IP-адрес источника. Кроме того, при выполнении своих атак злоумышленники могут изменять и другие поля в заголовке IP. Поэтому аналитикам по вопросам безопасности важно понимать суть различных полей в заголовках IPv4 и IPv6.

В таблице приведены некоторые наиболее распространенные атаки, связанные с IP.

| **Методы IP-атак** | **Описание** |
| --- | --- |
| **Атаки на основе ICMP**  | злоумышленники используют сообщения ICMP: эхо-запросы (ping) — для обнаружения подсетей и узлов в защищенной сети и для лавинных DoS-атак, а перенаправления ICMP — для изменения таблицы маршрутизации узла |
| **Атаки по методу умножения и отражения** | хакеры пытаются лишить законных пользователей доступа к информации или службам |
| **Атаки с подменой адреса** | субъекты угрозы подменяют IP-адрес источника в IP-пакете для выполнения открытой подмены или подмены вслепую |
| **Атака через посредника (MITM)**  | киберпреступники внедряются между источником и назначением для прозрачного мониторинга, захвата и контроля обмена данными. Они могут прослушивать, проверяя собранные пакеты, или изменять пакеты и пересылать по первоначальному целевому адресу |
| **Перехват сеанса**  | злоумышленники получают доступ к физической сети, а затем используют атаку через посредника для перехвата сеанса |

## Атаки на основе ICMP

Злоумышленники используют ICMP для разведывательных атак и сканирования в сети. Они могут запустить атаку для сбора информации, чтобы определить топологию сети, узнать, какие узлы активны (доступны), определить операционную систему узла (создание цифрового отпечатка ОС), а также состояние межсетевого экрана. Хакеры также используют ICMP для DoS-атак.

**Примечание.** ICMP для IPv4 (ICMPv4) и ICMP для IPv6 (ICMPv6) подвергаются атакам аналогичных типов.

В сетях должна применяться строгая фильтрация на основе списков контроля доступа (ACL) ICMP на границе сети, чтобы избежать зондирования ICMP из Интернета. Аналитики по безопасности должны быть в состоянии обнаружить атаки, связанные с ICMP, просматривая захваченный трафик и файлы журналов. В крупных сетях устройства обеспечения безопасности, например, межсетевые экраны и системы обнаружения вторжений (IDS), должны обнаруживать такие атаки и выдавать предупреждения для аналитиков по безопасности.

В таблице представлены сообщения ICMP, которыми обычно интересуются киберпреступники. 

| **ICMP сообщения, которые используют злоумышленники** | **Описание** |
| --- | --- |
| **Эхо-запрос и эхо-ответ ICMP**  | используются для выполнения проверки узлов и DoS-атак |
| **Сообщение ICMP о недостижимости**  | необходимы для выполнения разведывательных атак и сканирования сети |
| **Ответ ICMP с маской**  | требуются для составления карты внутренней IP-сети |
| **Перенаправления ICMP**  | позволяют спровоцировать целевой узел на отправку всего трафика через взломанное устройство и провести атаку через посредника (MITM) |
| **Обнаружение маршрутизатора ICMP**  | используется для вставки фиктивных записей маршрута в таблицу маршрутизации целевого узла |

<!-- 3.6.4 -->
Сеть становится усилителем атаки отражением, если пересылает направленные рассылки; это закрывают отключением пересылки и фильтром широковещательного адреса на границе.

1. Топология: наша сеть **192.168.1.0/24** за пограничным маршрутизатором **R1**; **ISP** — сторона провайдера.
2. Наследие старой настройки. На внутреннем интерфейсе G0/0/1 включена пересылка направленных рассылок — **ip directed-broadcast**; **show ip interface gigabitethernet0/0/1** подтверждает: **Directed broadcast forwarding is enabled**.
3. Проверка в режиме **«Симуляция»**. Один эхо-запрос снаружи на широковещательный адрес нашей сети — **ping 192.168.1.255** с ISP. R1 пересылает его внутрь как широковещательный кадр, коммутатор рассылает по всем портам узлов, и каждый узел шлет эхо-ответ: один запрос снаружи — несколько ответов. Так сеть становится усилителем для атаки отражением.
4. Защита на R1. Пересылку выключают — **no ip directed-broadcast** на внутреннем интерфейсе (так и должно быть по умолчанию). На входе со стороны провайдера добавляют список: **access-list 130 deny ip any host 192.168.1.255**, затем **permit ip any any**, и применяют его — **ip access-group 130 in** на G0/0/0.
5. Та же проверка вживую. Тот же **ping 192.168.1.255** снаружи теперь дает `U.U.U` — запрос отброшен на границе; обычный **ping 192.168.1.10** проходит (`!!!!!`). **show access-lists 130** показывает на запрещающей строке счетчик совпадений.
6. Итог: на внутреннем интерфейсе — **no ip directed-broadcast**; на входе от провайдера — ACL против широковещательного адреса. Проверка: запрос на 192.168.1.255 отброшен и посчитан, обычный трафик проходит.

## Атаки по методу умножения и отражения

Злоумышленники часто используют методы лавинообразного умножения данных и отражения для создания DoS-атак. Один из таких методов — Smurf-атака, при которой злоумышленник перегружает узел жертвы ответами множества других узлов в два этапа.

![](./assets/3.6.5.svg)
<!-- /courses/ensa-dl/ae8e8c80-34fd-11eb-ba19-f1886492e0e4/aeb3eed4-34fd-11eb-ba19-f1886492e0e4/assets/c5e04840-1c46-11ea-af56-e368b99e9723.svg -->

1.  **Лавинообразное умножение данных** – злоумышленник пересылает сообщения эхо-запроса ICMP большому числу узлов. Эти сообщения содержат исходный IP-адрес жертвы.
2.  **Отражение** – все эти узлы отвечают на поддельный IP-адрес жертвы и перегружают его.

**Примечание.** В настоящее время используются более новые формы атак по методу умножения и отражения, например, атаки на основе DNS и атаки по NTP с умножением данных.

Киберпреступники также используют атаки с исчерпанием ресурсов. Эти атаки могут перегрузить ресурсы целевого узла и вызвать его сбой, или загрузить ресурсы сети и существенно повлиять на ее работу.

## Атаки с подменой адреса

Атаки с подменой IP-адреса происходят, когда злоумышленник создает пакеты с ложной информацией об IP-адресе источника, чтобы скрыть личность отправителя или выдать себя за легитимного пользователя. Хакер может получить доступ к данным, которые недоступны другими способами, или обойти конфигурации системы безопасности. Подмена адресов обычно применяется в рамках других атак, например в smurf-атаках.

Атаки с подменой могут быть с открытыми или слепыми.

* **Открытая подмена** – киберпреступник может видеть трафик, который передается между узлом и целевым объектом. Открытая подмена используется им для изучения пакета ответа от целевой жертвы. Целью открытой подмены может быть определение состояния межсетевого экрана, прогнозирование порядкового номера, а также перехват авторизованного сеанса.

* **Подмена вслепую** – хакер не может видеть трафик, который передается между узлом и целевым объектом. Подмена вслепую используется в DoS-атаках.

Атаки с подменой MAC-адресов используются, когда у злоумышленника есть доступ к внутренней сети. Он изменяет MAC-адрес своего узла на известный MAC-адрес целевого узла. Например, сервер с MAC-адресом AABBCC подключен к порту 1 коммутатора, а злоумышленник — к порту 2, и злоумышленник меняет MAC-адрес своего компьютера на AABBCC. Затем атакующий узел отправляет по сети кадр с только что заданным MAC-адресом. Когда коммутатор получает кадр, он проверяет MAC-адрес источника.

**Киберпреступник подделывает MAC-адрес сервера**

![](./assets/3.6.6-1.svg)

Коммутатор перезаписывает текущую запись в таблице CAM и назначает MAC-адрес новому порту: в примере адрес AABBCC переходит с порта 1 на порт 2. Затем он пересылает кадры, предназначенные для целевого узла, на атакующий узел.
