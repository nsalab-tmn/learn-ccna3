## Описание сценария

Список контроля доступа (ACL) — последовательность записей permit и deny, по которой маршрутизатор решает, пропустить пакет через интерфейс или отбросить его. Стандартный список контроля доступа проверяет только IPv4-адрес источника пакета. Записи просматриваются по порядку до первого совпадения, а в конце каждого списка действует неявная запись deny any, поэтому пакет, не подошедший ни под одну запись, отбрасывается. Именованный список контроля доступа обозначается не номером, а именем, которое говорит о его назначении.

Согласно сценарию, в сети компании работает файловый сервер File-Server с базой данных веб-приложений. Обращаться к нему должны только рабочая станция веб-менеджера PC1 и веб-сервер Web-Server, а трафик остальных узлов к файловому серверу нужно запретить. Старший сетевой администратор поручил вам создать на маршрутизаторе R1 стандартный именованный список контроля доступа File_Server_Restrictions, применить его к интерфейсу в сторону файлового сервера и проверить, что ограничение работает, а доступ к веб-серверу у всех компьютеров сохранился.

## Задачи лабораторной работы

- Проверить связь компьютеров с серверами до настройки списка контроля доступа
- Создать стандартный именованный список контроля доступа File_Server_Restrictions на маршрутизаторе R1
- Применить список к интерфейсу F0/1 маршрутизатора R1 и сохранить конфигурацию
- Проверить работу списка контроля доступа

## Описание топологии

Топология состоит из маршрутизатора R1, коммутаторов Switch0, Switch1, Switch2 и Switch3, компьютеров PC0, PC1 и PC2 и серверов Web-Server и File-Server: к каждому из четырех интерфейсов маршрутизатора R1 через свой коммутатор подключена отдельная сеть.
