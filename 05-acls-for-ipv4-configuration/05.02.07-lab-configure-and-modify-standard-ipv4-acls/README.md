## Описание сценария

Стандартный список контроля доступа (ACL) фильтрует пакеты только по адресу источника, поэтому его размещают как можно ближе к получателю — на исходящем направлении интерфейса, за которым находится защищаемая сеть. Нумерованный список задают командами access-list с номером, именованный — в режиме настройки списка, где у каждой записи есть порядковый номер; именованный список можно изменить, не удаляя: добавить записи с нужными номерами. Каждый список заканчивается неявным запретом всего остального, а команда show access-lists показывает записи и число совпадений с каждой.

Согласно сценарию, руководство ввело правила фильтрации для двух офисов за маршрутизаторами R1 и R3. В сеть компьютера PC-C (192.168.30.0/24) должны попадать только узлы сетей компьютеров PC-A и PC-B, а в сеть компьютера PC-A (192.168.10.0/24) — только узел PC-C и сеть компьютера PC-D; позже правила меняются, и в сеть PC-A допускают еще и сеть сервера в Интернете. Вам, сетевому специалисту, нужно проверить связь до фильтрации, настроить нумерованный список на R3 и именованный на R1, проверить их командами show и эхо-запросами, изменить именованный список по новым правилам и ответить на вопросы в форме ответов.

## Задачи лабораторной работы

- Проверить связь между сетями до фильтрации
- Настроить и проверить стандартный нумерованный список доступа на маршрутизаторе R3
- Настроить и проверить стандартный именованный список доступа на маршрутизаторе R1
- Изменить именованный список доступа, не удаляя его

## Описание топологии

Топология состоит из маршрутизаторов R1, Edge и R3, соединенных последовательными каналами, маршрутизатора ISP поставщика услуг с сервером 209.165.200.254 за маршрутизатором Edge, коммутаторов S1–S4 и компьютеров PC-A, PC-B (за R1), PC-C и PC-D (за R3).
